# JARVIS Future Features

## 1. Desktop Experience

Planned desktop capabilities include:

- full GUI
- settings page
- system tray
- background operation
- configurable routing
- backend lifecycle controls
- project-root management
- task history
- notification center
- desktop orb or pet


## 2. Voice Interaction

Target voice pipeline:

Wake Word
↓
Voice Activity Detection
↓
Speech-to-Text
↓
JARVIS Core
↓
Reasoning / Tool Routing
↓
Response
↓
Text-to-Speech


## 3. Possible Voice Stack

Possible technologies include:

Wake word
→ openWakeWord

Voice Activity Detection
→ VAD

Speech-to-text
→ faster-whisper

Text-to-speech
→ Piper or Kokoro

Speaker verification
→ owner voice verification


## 4. Computer Interaction

The long-term goal is for users to issue natural voice or text commands and have
JARVIS safely perform supported computer tasks.

Computer interaction should grow through explicit capabilities rather than by
granting unrestricted shell access.


## 5. RAG Knowledge System

Planned RAG capabilities include:

- Markdown knowledge sources
- document chunking
- embeddings
- vector search
- metadata filtering
- source-aware retrieval
- project knowledge
- technical documentation
- user-added knowledge sources

Future formats may include:

- PDF
- DOCX
- JSON
- source code
- structured database content


## 6. Long-Term Memory

JARVIS should eventually maintain persistent memory for useful long-lived
information such as:

- user preferences
- previous decisions
- recurring workflows
- project context
- assistant configuration

Long-term memory should remain logically separate from RAG knowledge.


## 7. Background Assistance

Future JARVIS versions may support:

- long-running tasks
- scheduled tasks
- conditional monitoring
- task completion alerts
- background services

Background functionality must remain visible and controllable by the user.
