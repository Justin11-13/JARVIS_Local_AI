## Conflicting：实际行为或数据契约冲突

1. **JARVIS 笔记位于 Vault，但普通 JARVIS 查询不查该域**。例如“上次 JARVIS 做到哪里？”路由只给 `('jarvis',)`；Vault 中所有笔记是 `knowledge_domain=obsidian`。需要内容类别与来源位置分开建模。
2. **日期字段不一致**。Wiki 使用 `updated: 2026-09-05`，loader 只取 updated_at；8 篇共享笔记的 updated_at 全为空。新建工具补 created，但 loader 也没有保留 created。
3. **现有权威标签不参与排序**。实现记录的 authority 是 project-source，当前分析是 personal，target 是 user-requirement；retriever 不认识这些标签与拟定新等级之间的映射。
4. **Roadmap 标为 current**。该值目前表示“这份计划笔记仍有效”，不能直接推断“其中功能已实现”；需要 note_type 与 status 分开判断，不能只提高 current 分数。
5. **生成记忆的目录与新规划不同**。当前 `MemoryManager.preview` 默认 `JARVIS/Memory/{type}/{uuid}.md`，例如 decision/preference 小写单数；新计划要求 Decisions/Preferences。目前无专用子类路由，应先统一约定再新增。
6. **精确检索仍受语义门槛限制**。keyword bonus 只增加 score，RAGService 最终按原 similarity 过滤，符号命中没有独立保留通道。
7. **Heading 跳级错误已复现**。`# A → ### B → ### C` 返回路径 A/B/C；C 应与 B 同级。不能只因常规 H1/H2/H3 测试通过就认为任意 Markdown 都正确。
